# RSA Encryption Alternatives Analysis

## Problem Background

The current `packages/utils/src/rsa.ts` file uses Node.js's `crypto` module, which cannot be used in browser environments. We need to find browser-compatible alternatives.

## Existing Alternatives

### 1. Web Crypto API (Recommended)

**File Location**: `packages/utils/src/rsa-web.ts`

**Advantages**:
- Native browser support, no additional dependencies
- Excellent performance, implemented by browser's underlying layer
- High security, compliant with Web standards
- Supports modern encryption algorithms

**Features**:
- Key format: JWK (JSON Web Key)
- Default algorithm: RSA-OAEP with SHA-256
- Default key length: 2048 bits
- Asynchronous API

**Usage Example**:
```typescript
import { generateWebRSAKeyPair, webRSAEncrypt, webRSADecrypt } from './rsa-web';

// Generate key pair
const keyPair = await generateWebRSAKeyPair({
  modulusLength: 2048,
  hashAlgorithm: 'SHA-256'
});

// Encrypt
const encrypted = await webRSAEncrypt('Hello World', keyPair.publicKey);

// Decrypt
const decrypted = await webRSADecrypt(encrypted, keyPair.privateKey);
```

### 2. Node-forge (Already Exists)

**File Location**: `packages/utils/src/crypto/forge.ts`

**Advantages**:
- Pure JavaScript implementation, cross-platform compatible
- Supports PEM format keys (compatible with Node.js)
- Complete functionality, supports multiple encryption algorithms

**Features**:
- Key format: PEM
- Algorithm: RSA-OAEP
- Default key length: 1024 bits
- Requires additional dependencies

### 3. Existing Web Crypto Manager (Already Exists)

**File Location**: `packages/utils/src/crypto/web.ts`

**Advantages**:
- Based on Web Crypto API
- Unified interface design
- Supports long text encryption

## Compatibility Test Results

Verified through `packages/utils/test/rsa-compatibility.test.ts`:

✅ **Node.js crypto ↔ Forge**: Fully compatible
- PEM keys generated by Node.js can be used by Forge
- PEM keys generated by Forge can be used by Node.js
- Encryption/decryption results are consistent

⚠️ **Web Crypto API**: Requires format conversion
- Uses JWK format, not directly compatible with PEM format
- Requires additional format conversion tools

## Recommended Solutions

### For New Projects
Recommend using **Web Crypto API** (`rsa-web.ts`) because:
1. Native browser support with best performance
2. No additional dependencies
3. Compliant with modern Web standards
4. High security

### For Existing Projects
Recommend using **Node-forge** (`crypto/forge.ts`) because:
1. Fully compatible with existing Node.js code
2. No need to modify existing key formats
3. Can seamlessly replace Node.js crypto

## Migration Guide

### Migrating from Node.js crypto to Web Crypto API

```typescript
// Original code (Node.js)
import { generateKeyPairSync, rsaEncrypt, rsaDecrypt } from './rsa';

const keyPair = generateKeyPairSync(2048);
const encrypted = rsaEncrypt('message', keyPair.publicKey);
const decrypted = rsaDecrypt(encrypted, keyPair.privateKey);

// New code (Web Crypto API)
import { generateWebRSAKeyPair, webRSAEncrypt, webRSADecrypt } from './rsa-web';

const keyPair = await generateWebRSAKeyPair({ modulusLength: 2048 });
const encrypted = await webRSAEncrypt('message', keyPair.publicKey);
const decrypted = await webRSADecrypt(encrypted, keyPair.privateKey);
```

### Migrating from Node.js crypto to Forge

```typescript
// Original code (Node.js)
import { generateKeyPairSync, rsaEncrypt, rsaDecrypt } from './rsa';

const keyPair = generateKeyPairSync(2048);
const encrypted = rsaEncrypt('message', keyPair.publicKey);
const decrypted = rsaDecrypt(encrypted, keyPair.privateKey);

// New code (Forge) - Fully compatible
import { ForgeCryptoManager } from './crypto/forge';

const forgeManager = new ForgeCryptoManager();
const keyPair = await forgeManager.generateKeyPair();
const encrypted = await forgeManager.encrypt(keyPair.publicKey, 'message');
const decrypted = await forgeManager.decrypt(keyPair.privateKey, encrypted);
```

## Security Considerations

1. **Key Length**: Recommend using 2048 bits or higher
2. **Padding Mode**: All solutions use OAEP padding for high security
3. **Hash Algorithm**: Web Crypto API defaults to SHA-256, Forge also supports it
4. **Key Storage**: JWK format is better for web applications, PEM format is better for servers

## Summary

The project already has complete RSA encryption alternatives:

1. **Web Crypto API** - Best choice for modern browsers
2. **Node-forge** - Fully compatible choice with existing code
3. **Existing Crypto Manager** - Unified encryption interface

It is recommended to choose the appropriate solution based on specific use cases and ensure thorough compatibility testing.
